DepScan

Sistema web de detección y remediación de dependencias vulnerables para proyectos npm y PyPI

El problema

El código que no escribimos también nos puede atacar

  • Un proyecto moderno usa cientos o miles de librerías de terceros, y la mayoría llega de forma indirecta (transitiva).
  • Cuando se publica una falla en una de ellas, el equipo no se entera si no cruza "lo que tengo instalado" con "lo que ya se sabe que está roto".
  • Saber a qué versión actualizar sin romper el proyecto ni caer en otra versión vulnerable es prueba y error.

Antecedentes

No es un riesgo teórico

2017

Equifax

Apache Struts sin parchear (CVE-2017-5638). El parche existía desde el 6 de marzo, unos dos meses antes del ataque. Se expusieron datos de unos 147 millones de personas.

2021

Log4Shell

Una falla en la librería de registro Log4j (CVE-2021-44228) permitió ejecutar código remoto en miles de sistemas que ni sabían que la usaban.

Lo que ya existe

Bases públicas y gratuitas: OSV (Google) y NVD (NIST) publican las vulnerabilidades. Herramientas: npm audit, pip-audit y OSV-Scanner (gratuitas, de consola, en inglés, un ecosistema o sin interfaz web) y Snyk (comercial). El valor no está en los datos, sino en procesarlos bien y explicarlos.

Objetivo

Detectar, priorizar y decir cómo corregir

Objetivo general: desarrollar un sistema web que detecte las dependencias vulnerables de proyectos npm y PyPI a partir de sus versiones exactas, las priorice por severidad y entregue al usuario los pasos concretos para remediarlas.

  • Leer package.json, package-lock.json y requirements.txt y obtener la versión exacta de cada dependencia directa y transitiva.
  • Consultar OSV en lote y enriquecer con NVD (CVSS oficial).
  • Aplicar lógica propia: deduplicación CVE/GHSA/PYSEC, prioridad y semáforo de riesgo.
  • Recomendar la versión segura verificada contra todos los avisos del paquete.
  • Ofrecer web, reportes HTML/PDF, historial, login y CLI para CI.
  • Medir los resultados contra herramientas existentes con un benchmark reproducible.
Alcance

Qué hace y qué no hace

Dentro del alcance

  • Ecosistemas npm y PyPI, con dependencias transitivas.
  • Subir archivos o carpeta, o escanear un repo de GitHub por commit.
  • Repos privados con la cuenta de GitHub conectada.
  • Remediación: versión recomendada, comandos, overrides, mitigaciones y parches.
  • Historial, comparación antes/después, reportes HTML y PDF.
  • CLI con código de salida para detener entregas inseguras.

Limitaciones declaradas

  • No descubre fallas nuevas: solo las ya publicadas en OSV/NVD.
  • No sabe si el código usa la función afectada (alcanzabilidad).
  • Sin lockfile la precisión baja; se avisa o se estima, y se marca como estimación.
  • No aplica las correcciones automáticamente.
  • Requiere internet (se mitiga con caché de 24 h).
Cómo funciona

Un escaneo en 7 pasos

1

Leer

Detecta y parsea los manifiestos (rangos, -r, extras, comentarios).

2

Resolver

Versión exacta desde el lockfile; sin él, avisa o estima.

3

Consultar

OSV querybatch: hasta 1000 paquetes por lote.

4

Detallar

Severidad, alias y versiones corregidas, con caché.

5

Enriquecer

CVSS oficial de NVD por CVE (opcional).

6

Analizar

Deduplica, separa directa/transitiva, prioriza y calcula la versión segura.

7

Reportar

Semáforo, web, HTML/PDF y código de salida para CI.

La aplicación

Escanear es arrastrar una carpeta o pegar un repo

  • Subir archivos o carpeta: el navegador filtra solo los manifiestos e ignora node_modules.
  • Repositorio de GitHub: se analiza un commit exacto, así el resultado es reproducible.
  • Mis repos de GitHub: con la cuenta conectada, se listan también los privados.
  • Opciones: incluir dependencias de desarrollo, estimar sin lockfile y CVSS oficial de NVD.
  • Login con Google o GitHub; el escaneo anónimo pasa a la cuenta al iniciar sesión.
La aplicación

El resultado: semáforo, severidades y cada hallazgo

  • Semáforo de riesgo global y conteo por severidad.
  • Rama y commit analizados, versión del escáner y duración (7,2 s para 1091 dependencias).
  • Tabla filtrable por severidad, directa/transitiva, ecosistema y desarrollo.
  • Cada paquete muestra sus CVE ya deduplicados y la versión recomendada.
  • Reporte en pantalla y descarga en HTML y PDF.
La aplicación

No solo dice qué está mal: dice cómo arreglarlo

  • Versión recomendada dentro de la misma versión mayor, con aviso si exige un salto mayor.
  • Todas las versiones seguras, verificadas contra todos los avisos del paquete, no solo el actual.
  • Comandos listos para copiar: npm install, overrides para transitivas, pip install.
  • Si no se puede actualizar: mitigaciones del aviso y por tipo de falla (CWE), con enlaces a los parches.

Nuestra diferencia

Lo que DepScan hace distinto

Remediación verificada

Otras herramientas sugieren la "versión corregida" de un aviso, que puede tener otra falla. DepScan evalúa cada versión candidata contra todos los avisos del paquete.

Pensado para quien aprende

Web en español, explicación de cada falla, comandos listos para copiar y mitigaciones cuando actualizar no es posible.

Honesto con sus límites

Sin lockfile no inventa versiones: las marca como no determinables o como estimación. Las limitaciones se muestran en la propia app.

Evidencia reproducible

Cada escaneo registra commit, fecha y versión del escáner, con reporte PDF. El benchmark se puede repetir con un comando.

Calidad y seguridad

La propia aplicación cumple lo que predica

  • 97 pruebas automatizadas sin internet: las fuentes externas se simulan gracias a los puertos.
  • El CI ejecuta DepScan sobre su propio código y bloquea el build si aparece una falla alta.
  • Diccionario de datos generado automáticamente desde el esquema real de la base.
  • Documentación RUP completa (FD01 a FD06) con decisiones de arquitectura (ADR).
  • Login OAuth con Google y GitHub; tokens cifrados con AES-256-GCM.
  • Cookies HttpOnly, Secure y SameSite; sesión nueva tras autenticarse.
  • Límite de peticiones por minuto en el escaneo.
  • Repos privados visibles solo para su dueño.

Conclusiones

Conclusiones

  • Se construyó y desplegó un sistema web que detecta dependencias vulnerables en npm y PyPI a partir de versiones exactas, incluidas las transitivas.
  • En el benchmark, DepScan encontró todas las fallas que reporta npm audit y unió los avisos duplicados, sin hallazgos perdidos.
  • El aporte principal es la remediación verificada: una versión segura contra todos los avisos, los comandos para aplicarla y mitigaciones si no se puede actualizar.
  • La arquitectura hexagonal permitió reutilizar el mismo motor en web, API y CLI, y probarlo sin depender de internet.
  • Las limitaciones se declaran: el sistema informa fallas conocidas, no la explotabilidad real.
